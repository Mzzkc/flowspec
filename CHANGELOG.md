# Changelog

## [Unreleased]
### Added
- **Memory budget** (`--memory-limit`, `FLOWSPEC_MEMORY_LIMIT`, default 2G): every allocation is counted and each analysis stage boundary stops the run with `memory budget exceeded after <stage>` and exit 1 once the budget is crossed. Added after an uncapped run exhausted a 15 GB host on 2026-11-10.
- **Streaming Python reference index** (`flowspec/src/pyindex/`, design in `docs/design/streaming-index.md`): each file is parsed once and reduced to a per-file fact set persisted under `.flowspec/index/`; only the export table stays resident; resolution runs per file against it and emits posting lists. For Python-only analyses `trace`, `diagnose` and `analyze` all read the index: all thirteen diagnostic patterns, entities, flows, module summaries, boundaries and the dependency graph are computed from posting lists. Re-runs re-parse only changed files and re-resolve only their import closure. Callers are reported as certain or possible with file:line and a reason; an empty answer says what was searched. Module-level variables are definitions with reference sites. Measured 2026-11-11 (Ronin, 2 GB cap): see `docs/design/streaming-index.md` and the oracle in `scripts/oracle/`.
- **CI accuracy gate**: `flowspec-cli/tests/oracle_gate.rs` scores the release binary with the oracle on the committed fixtures under `tests/oracle/` and fails on any missed or wrongly claimed caller; `cargo tarpaulin --fail-under 87` enforces the coverage floor.
- **Diagnostic patterns read only the export table and the posting lists.** The per-file facts the last three patterns needed (`phantom_dependency`, `missing_reexport`, `stale_reference`: import list, reads per scope, `__all__` names, module-scope bindings) are folded into the export table at build time; no pattern decodes a fact file. Index version 6.
- **Authority projection uses one line table per file** instead of rescanning the file for every binding range and every loss range. Marianne warm `analyze`: projection 340 ms -> 135 ms.
- **One index loss per file and kind**: a file with two hundred annotations is one `capability_unavailable` loss carrying two hundred ranges, not two hundred losses. Marianne `analyze`: 8,850 losses and a 23 MB manifest -> 333 losses and 15 MB; warm diagnose 279 MB -> 223 MB.
- **Reading an alias of an alias is a certain site to the variable named**: `SkipTarget = SheetSpan` read in an annotation marks `SkipTarget` consumed (and `SheetSpan` possibly), instead of leaving both as possible.
- **Importing a module variable is a site**: `from .base import _logger` reaches the variable, so a private module-level binding consumed only through imports is not `data_dead_end`.
- **`global` rebinding reads the module variable**: an assignment under `global x` inside a function binds the module scope instead of shadowing it, so lazily initialised module singletons are not `data_dead_end`.
- **Four false-positive classes found by adjudicating Marianne diagnose on the index** (30 findings per pattern against the ast oracle): names read only in annotations, quoted forward references and `__all__` entries now count as reads (`data_dead_end`, `phantom_dependency`); a module variable read is a certain reference even when its value cannot be typed (constants used as default values or in expressions); a decorated method (`@property`, `@field_validator`, route or hook decorators) or one named by a string literal in its file (dispatch tables) is never `orphaned_impl`.
- **Sites carry a column**: two calls to the same target on one line are two sites (they were deduplicated to one); index version 5.
- **Forward site queries are O(log N)**: the index keeps a by-owner permutation of the site array, so "what does this definition reach" is a binary-searched slice like "what reaches it"; manifest entity ids are computed once per index instead of per finding. Marianne warm `diagnose`: index diagnostics 1.6 s -> 0.1 s, whole run 2.3 s -> 0.72 s.
- **Python never builds the whole-program graph.** `analyze` and `diagnose` send every Python file to the reference index and only other languages to the graph; a mixed tree merges both (closes #37). Custody, finding proofs, the authority's analysis-graph projection and the Python prerequisite losses (`capability_unavailable`/type_flows per annotation, `unresolved_type` for an unbound annotation root, `unresolved_reference` for a builtin namespace operation, `unsupported_construct` for `match`, `unresolved_import` for an unplaceable relative import) are produced from the index at build time and persisted in `losses.bin` (index version 4). On Marianne (323 Python files, 2 JavaScript) warm `diagnose` no longer parses the Python graph.
- **Index findings match the graph producer's contract**: entity ids are `file.py::name` (directory-prefixed only on collision); public top-level functions are never `data_dead_end` findings; a definition decorated by a project decorator counts as consumed; lambda parameters shadow outer names; decorator contract violations name the bare method.
- **Trace memory-budget test** uses a 400-file tree: the index holds far less than the graph did, and the 60-file fixture sat exactly at the 1 MiB boundary (CI allocator rounding passed it).
- **A checked-in `.flowspec/index` is untrusted input**: every cache file is tagged with a keyed SHA-256 under a per-user key kept outside the repository (`$FLOWSPEC_CACHE_KEY`, else `$XDG_CACHE_HOME/flowspec/index.key`, else `~/.cache/flowspec/index.key`, created 0600), so nothing this user did not write is ever decoded; temporary files are created exclusively without following symlinks; cache files are decoded under a 256 MiB bound, a fact set whose scope, owner, parent or class indices fall outside its own definitions is rebuilt from source, retained sites must name definitions in the rebuilt export table, a symlinked `.flowspec`, `index` or `facts` directory is refused, and cleanup deletes only regular files named like a fact file.
- **Index fact files are keyed by path and content**: two identical files in different directories no longer share one fact set, which on a warm rebuild gave the second file the first file's path and module (`trace` then reported the symbol missing). Index version bumped to 3; stale indexes rebuild.
- **Concurrent index builds are safe**: each atomic write uses a temporary file unique to the process and call, so parallel builds of one index (parallel tests) never rename each other's half-written file.
- **Oracle scores traces by full root-relative symbol path**, so same-named fixture files in different directories are distinct cases.
- **Script-style imports resolve**: an import that is not a package path is tried relative to each ancestor directory of the importing file (`from sibling import f`, `from repository.repo import x` beside `api/`), so circular and layer fixtures laid out as scripts resolve like packages.
- **Oracle harness** (`scripts/oracle/`): `ast`-derived ground truth for callers and an adjudicator for diagnose findings, the basis for measuring false negatives and false positives in CI.
- **Cross-file flow tracing** (CF): `import m; m.f()` now traverses module boundaries — flowspec is useful on real multi-file codebases.
- **Dotted-import call resolution** (A1): `module.func()` calls create cross-file call edges.
- **Config validation**: warns on unknown top-level config keys (e.g. `analysis.ignore` → suggests `exclude`).
### Fixed
- **Multi-segment directory excludes** now filter contents (`tests/fixtures/` etc. were silently ignored → dogfood 1367→597 findings, test-pollution eliminated).
- 5 pre-existing cycle19/21 `issues-filed.md` process-gate tests re-homed to `#[ignore]` (gitignored workspace artifacts).

- CLI: `analyze`, `diagnose`, `trace`, `diff`, `init`; formats: yaml/json/sarif/summary.
- Exit-code contract: 0 clean / 1 error / 2 findings (CI gate).
