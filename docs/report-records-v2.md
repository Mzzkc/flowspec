# Report records v2

The public `expand_report_records` reader accepts both `flowspec.report.records.v1` and `flowspec.report.records.v2`. V2 retains an acyclic node/shape table with compact numeric tags (`[-1, child...]` for arrays and `[shape_id, child...]` for objects). Graph tables remain in their original authority slot; an attempted additional graph interning enlarged ordinary reports and was not retained. V2 scalar strings beginning with `~` are escaped by an extra `~`; exact lowercase 64-hex `sha256:` strings use `~` followed by their hex payload. Expansion validates these forms and restores every byte. V1 keeps its original unwrapped graph slot and literal scalar strings. Unknown versions, malformed wrappers and invalid references fail closed.

Report ABI remains v1. All seventeen authority keys, fourteen identity inputs, legacy sections, graph tables v1/v2 readers, findings, losses, state and source ranges survive full expansion. Producer expansion equality is required before emitting packed bytes. The original byte and source ratio guards are unchanged. A new consumer must expand report records before reading graph tables, as the public typed Manifest reader does. This changed wire version requires independent affected consumer judgment; source tests do not admit the migration or qualify launch.

SARIF reports also reuse this exact v2 table, stored in the standard extension property bag `runs[0].properties.report_records`, for the custom authority at `runs[0].properties.flowspec`. Standard SARIF results, rules, locations, related evidence, fingerprints and execution notifications remain ordinary JSON. Call the same public `flowspec::commands::expand_report_records` reader on the complete SARIF value before inspecting the custom authority fields. It returns the original SARIF shape with all authority fields expanded and removes the record table; malformed tables and missing authority slots fail closed. Encoded reports produced by FLOWSpec contain exactly one run. Plain SARIF passes through unchanged.

The CLI `expand-report` command has an explicit 128 MiB (134,217,728 byte) raw stdin acquisition capacity. It reads at most capacity plus one byte, then refuses greater input before JSON parsing or output. Exactly-capacity valid JSON and plain unencoded reports below that capacity remain eligible. This raw acquisition capacity is separate from the unchanged 64 MiB cumulative expanded record-node budget and the producer sizing guards. It bounds the acquisition buffer; it does not promise total process memory, elapsed time, aggregate quotas, or unlimited report support.
