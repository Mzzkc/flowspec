# Cache, trace and type-operation API

`analyze_with_options` and `analyze_with_registry_and_options` accept an `AnalysisOptions` value. `mode` selects full parsing or incremental reuse; `cache_dir` selects the cache location. A structured provider has a versioned `structured_parser_identity` and returns `ParsedFile { ir, report }`. Its report binds the exact file, language, source byte count and SHA-256, adapter/grammar versions, capability dispositions and located events. Legacy or unbound output is refused. Unknown capability evidence survives cache reuse and makes the affected diagnostics incomplete.

The default built-in path in this component currently has no structured provider. `analyze --incremental` records `structured_adapter_not_joined` as a cache fallback and performs full parsing. Native incremental operation remains unqualified. The library's injected provider path performs per-file reuse, rebuilds a fresh global graph, resolves it again, and exposes actual hit/parse/fallback counts in `AnalysisResult.cache_stats`. The current serialized cache provenance/report-identity contract also needs integration qualification; operation counters alone do not establish native full/warm equivalence.

Cache keys include exact content, producer version/build/tree, registry, adapter, declared/effective language, policy identity, root/file identity, parser depth and provider identity. Reads are bounded and checksum checked. Writes use a namespace pinned by Linux directory handles, an exclusive nonblocking writer claim, unique temporary files, synchronization and atomic replacement. A failed cache operation falls back to parsing; it does not add semantic uncertainty by itself.

`trace --report --format json` (or YAML, SARIF, summary) returns exact binding identities and ordered real edge hops, source locations, query execution, scoped losses and continuation metadata. Depth or detail limits produce exit 3. `flowspec_trace` exposes the same query through packaged MCP stdio, with equal JSON text and structured content. The query payload is bounded to 9,000 bytes in JSON/YAML; counts and explicit truncation survive omitted details. Continuation identifies omitted/frontier paths; an executable pagination cursor is not yet implemented. Legacy trace arrays remain available through the existing command without `--report`.

Type-operation records currently cover simple Python construction, parameter use, and returned constructor transformations supported by resolved references and exact source bindings. Annotation-only references, property names, keyword labels, shadowed constructors and discarded conversion results are excluded. The extractor uses captured source text for a secondary AST pass; it has not qualified complete cross-language type dataflow or the warm performance budget. Existing located type-evidence debt remains visible. These APIs are not launch acceptance evidence.
